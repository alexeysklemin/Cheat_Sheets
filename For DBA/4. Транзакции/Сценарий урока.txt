История одного ноутбука: Транзакции в действии
На складе интернет-магазина «Ромашка» числился всего один ноутбук модели SuperBook X1 (product_id = 101). Его цена — 50 000 рублей. За этот единственный экземпляр развернулась настоящая драма с участием трех покупателей: Алексея, Дмитрия и Сергея.
Акт 1. Алексей и пустой кошелек
Алексей первым нажал кнопку «Купить». Сервер магазина немедленно открыл транзакцию, чтобы зарезервировать товар.
BEGIN;
SELECT stock_count FROM products WHERE product_id = 101 FOR UPDATE;
-- Результат: 1 (Ноутбук есть, строка заблокирована для других)
Убедившись, что товар в наличии, система попыталась списать деньги со счета Алексея (user_id = 1). Но тут выяснилось неприятное: на балансе было всего 45 000 рублей. Сработало ограничение базы данных CHECK (balance >= 0), и запрос вернул ошибку.
Поскольку условие «списания денег» не выполнилось, вся цепочка действий стала бессмысленной. Магазин не может отдать товар, не получив оплату. Система приняла решение отменить всё, что успела сделать в рамках этой попытки.
ROLLBACK;
-- Итог: Ноутбук вернулся на склад (stock_count снова 1), блокировка снята. Алексей остался без покупки.
Акт 2. Битва Дмитрия и Сергея
Пока Алексей разбирался со своим банком, в магазин зашел Дмитрий. Он тоже хотел этот ноутбук. Его клиент открыл свою транзакцию и попытался захватить тот же самый товар.
-- Сессия Дмитрия
BEGIN;
SELECT stock_count FROM products WHERE product_id = 101 FOR UPDATE;
Но в ту же миллисекунду свои действия начал Сергей (user_id = 3). Его транзакция оказалась чуть быстрее или просто удачнее по таймингу сервера. Сергей успешно заблокировал строку с товаром.
-- Сессия Сергея
BEGIN;
SELECT stock_count FROM products WHERE product_id = 101 FOR UPDATE;
-- Успех! Строка захвачена Сергеем.
Дмитрий теперь вынужден ждать. Его запрос SELECT ... FOR UPDATE завис в состоянии ожидания, пока Сергей не закончит свои дела. Это и есть Изоляция: Дмитрий не может даже посмотреть актуальное состояние товара, пока Сергей владеет блокировкой.
Акт 3. Триумф Сергея
Сергей прошел все проверки. Деньги на его счету были, товар был зарезервирован. Система выполнила финальные изменения: списала товар со склада, уменьшила баланс Сергея и создала запись о заказе.
UPDATE products SET stock_count = stock_count - 1 WHERE product_id = 101;
UPDATE users SET balance = balance - 50000 WHERE user_id = 3;
INSERT INTO orders (user_id, product_id, amount) VALUES (3, 101, 50000);
COMMIT;
-- Итог: Данные записаны на диск (Долговечность). Ноутбук официально продан Сергею.
Как только Сергей сделал COMMIT, блокировка с товара снялась. Запрос Дмитрия, который так долго ждал, наконец-то выполнился. Но вместо ожидаемой единицы он увидел нуль.
Увидев, что stock_count = 0, логика приложения Дмитрия поняла: покупать нечего. Нет смысла продолжать транзакцию.
ROLLBACK;
-- Итог: Дмитрий закрыл транзакцию без изменений. Он узнал, что опоздал.
Резюме истории
Атомарность: У Алексея не получилось «полкупли». Либо всё (товар + списание), либо ничего.
Изоляция: Дмитрий не смог вмешаться в процесс покупки Сергея, пока тот не закончил.
Согласованность: На складе никогда не было -1 ноутбука. База всегда оставалась в корректном состоянии.
Долговечность: После COMMIT Сергея запись о продаже осталась в базе навсегда, даже если бы сервер сразу после этого выключился.
